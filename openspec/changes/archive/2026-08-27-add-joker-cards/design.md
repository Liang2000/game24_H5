## Context

提示模块的可选卡片由 `HintScene` 中硬编码的 `VALUES = [1..13]` 决定，牌面标签统一由 `src/core/game.ts` 的 `faceLabel` 映射（A、J、Q、K 为特例，其余直接转字符串）。求解器 `solve(values)` / `isSolvable(values)` 对任意 `number[]` 做精确有理数求解，与牌面取值范围无关，因此 14、15 无需任何改动。动机见 proposal.md。

## Goals / Non-Goals

**Goals:**
- 提示模块可点选 15 张卡片（1–15），并在界面按 A–K、V、W 顺序展示。
- 小王 V（14）、大王 W（15）各限选 1 张；A–K（1–13）保持可重复。

**Non-Goals:**
- 不改动单人挑战的 52 张牌组与随机抽题（仍为 1–13）。
- 不改动组合速查的枚举范围与静态数据（仍为 1–13）。
- 不改动求解器与表达式校验；解法表达式继续以数字（14/15）而非 V/W 展示，与既有 J/Q/K 展示为 11/12/13 的行为一致。

## Decisions

1. **在 `FACE_LABELS` 中新增 `14: 'V'`、`15: 'W'`**，而非在 HintScene 内另建局部映射。
   - 理由：`faceLabel` 是牌面→标签的唯一来源，HintScene 的卡片与数字框均已复用；52 张牌组只迭代 1–13，不会受新增键影响。
   - 备选：在 HintScene 局部定义标签。缺点是与现有共享映射割裂，且数字框展示也需要用到。

2. **`VALUES` 直接扩展为 `[1..15]`**，沿用现有 5 列网格。
   - 15 张卡片在 5 列下恰为 3 整行（5+5+5），无需改布局坐标；当前已是 3 行（5+5+3），纵向空间足够。

3. **在 `pick(v)` 中用「若 `v >= 14` 且 `selected` 已含 `v` 则忽略本次点击」实现限选一张**。
   - 理由：最小改动，且天然配合「点已填框清空」——清空后即可重新点选。
   - 备选：动态切换卡片的 `setInteractive` 状态置灰。缺点是需要随每次选择/清空同步更新交互状态，复杂且无必要。

4. **求解器零改动**：`solve` / `isSolvable` 已对任意数字做精确有理数运算，直接支持 14、15。

## Risks / Trade-offs

- [15 张卡片 3 整行的纵向排布可能贴近下方按钮] → 实施时截图确认不重叠；现有坐标（卡片行高约 114px，按钮位于 y=720）预计仍有富余。
- [`faceLabel` 是共享函数，新增键可能被误以为影响牌组] → 牌组 `createDeck` 仍固定 1–13，新键仅提示模块会消费，文档已注明。

## Migration Plan

无需数据迁移；改动为纯前端代码，静态资产与 localStorage 记录均不受影响。回滚即还原 `VALUES` 与 `FACE_LABELS` 两处。
